# Alerty

Alerty — кроссплатформенная панель для наблюдения за серверами, контейнерами и сервисами и безопасного управления ими. Проект нацелен на удобный единый интерфейс для системных метрик, логов в реальном времени, статуса сервисов и контролируемых административных действий.

Текущая версия: **0.0.2a** — добавлен контейнерный HTTP-шлюз для подключения к Prometheus и Loki без передачи их секретов в браузер.

## Возможности прототипа

- обзор состояния серверов, сервисов, событий и системных ресурсов;
- анимированный график CPU/RAM и поток демонстрационных логов;
- список серверов с Linux и Windows;
- отдельные каталоги серверов, событий, живых логов и действий с поиском и фильтрами;
- переходы от сервера к его сервисам и метрикам, от события к логам, фиксация демо-действий в аудите;
- группировка лога по часовым интервалам или по серверам, сворачивание групп и фильтрация;
- подтверждение команды перезапуска сервиса в демо-режиме;
- адаптивная раскладка для широкого и мобильного экрана.
- контейнерный шлюз проверяет доступность Prometheus/Loki и проксирует их query API;

## Быстрый старт в Docker

1. Скопируйте `.env.example` в `.env`.
2. Заполните адреса Prometheus и Loki, доступные **из контейнера Alerty**.
3. Запустите `docker compose up -d --build` и откройте `http://127.0.0.1:8080` на машине с Alerty.
4. Проверьте API-ответ `/api/integrations` и строки состояния в левой панели.

По умолчанию порт опубликован только на `127.0.0.1`. Для удалённого доступа используйте VPN и TLS Nginx с авторизацией; пример location-конфигурации находится в `deploy/nginx-alerty-location.conf`. Не публикуйте Prometheus или Loki напрямую в интернет. Файл `.env` игнорируется Git и не должен отправляться в репозиторий.

При локальном открытии `index.html` без контейнера интерфейс остаётся в демонстрационном режиме. Эндпоинты интеграции доступны только при запуске через Node/Docker.

## Важно

В **0.0.2a** шлюз подключается к источникам и показывает их доступность, но экранные графики, логи, каталог узлов, события и аудит пока остаются демонстрационными. Следующий шаг — получить от владельца лаборатории сведения о таргетах, метках и версии экспортёров, затем связать ответ источников с интерфейсом. Команды управления пока не отправляются на реальные хосты.

## Что нужно для подключения домашней лаборатории

- Где будет запущен Alerty: ОС/архитектура машины, Docker Engine и Compose, адрес в LAN/VPN.
- Адрес Prometheus и способ доступа: URL/порт и, если включена защита, тип авторизации. Пароли и токены в чат не присылайте — они записываются только в локальный `.env` на машине Alerty.
- Список серверов, которые Prometheus уже видит, с ожидаемыми именами. Нужны labels из ответа `/api/v1/targets` (достаточно замазать внутренние домены, если хотите).
- Какие экспортёры установлены: `node_exporter` на Linux, `windows_exporter` на Windows, cAdvisor/Docker для контейнеров; для каждого — версия и какие метрики доступны.
- Нужны ли логи из Loki: адрес/порт и как называется label сервера (часто `host`, `instance` или `hostname`); пришлите пример набора labels и одну строку LogQL, которая уже работает в Grafana.
- Есть ли доступ только внутри LAN или через VPN. Alerty должен иметь сетевой маршрут к Prometheus/Loki; MAC-адрес для удалённой аутентификации не подходит.

После этого настроим соответствие «узел Alerty ↔ Prometheus labels ↔ Loki labels», проверим реальные CPU/RAM/Load Average и выведем логи отдельно по серверам и времени.

## Направление архитектуры

- интерфейс: web dashboard, доступный с ПК и мобильного браузера;
- серверная часть: API и PostgreSQL для учётных записей, хостов, устройств и аудита;
- метрики: Prometheus, `node_exporter` / `windows_exporter`, cAdvisor;
- логи: Loki и Grafana Alloy;
- графики: собственные обзорные карточки плюс Grafana для расширенного анализа;
- управление: отдельный узловой агент с минимальным набором разрешённых операций и защищённым соединением.
